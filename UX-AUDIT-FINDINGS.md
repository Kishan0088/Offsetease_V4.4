# OffsetEase V4.4 — UX / CRO / Accessibility Audit: Findings

**Target:** https://kishan0088.github.io/Offsetease_V4.4/
**Date:** 13 September 2026
**Commit audited:** `990ab81` (deployed site verified as matching local `HEAD`)
**Method:** Live testing in Chromium at 1024 / 1280 / 1440 / 1600 px desktop widths and 375×812 mobile; contrast ratios computed from live composited pixel values (including real photo pixels composited with the actual scrim gradient alpha); form behaviour tested by submitting a valid enquiry against the live endpoint; source verified in the deployed build.
**Frameworks applied:** Nielsen's 10 Usability Heuristics, WCAG 2.2 Level AA.

**Counts: 3 Critical · 13 Major · 7 Minor**

---

## Context: what already passes

This is a well-built site. Verified working: one `h1` per page across all 28 pages, no heading-level skips, zero unnamed links or buttons, zero missing `alt` attributes, a functioning skip link, a real focus trap with Esc handling and focus restoration in the mobile menu, correct `aria-expanded` / `aria-controls` wiring, `prefers-reduced-motion` honoured in 11 places, `.no-js` CSS fallbacks, and a fast critical path (~34 KB gzipped HTML+CSS+JS, 90 KB hero AVIF, video `preload="none"` gated behind `saveData` / reduced-motion / `<1024px`). **Performance is not a problem on this site.** The issues below are concentrated, not systemic.

## Findings

| # | Priority | Category | Issue | Standard / Principle | Impact | Exact Fix |
|---|---|---|---|---|---|---|
| C1 | **Critical** | Forms / CRO | The enquiry form is dead. `data-access-key=""` on `contact.html`. A fully valid enquiry submitted against the live site returned: *"This form is not connected yet. Please email info@offsetease.com."* Every submission is lost, and the user only learns this **after** completing 5 required fields + consent. | Nielsen #1 (Visibility of system status), #5 (Error prevention); WCAG 3.3.4 | Total. This is the site's **only** conversion mechanism across all 28 pages. 100% of form leads lost. | Set the Web3Forms access key in `src/render.mjs` (the `data-access-key` value) and rebuild. Until it is set, do not render a form at all — render the email/phone block instead, so nobody wastes effort on a form that cannot send. |
| C2 | **Critical** | Navigation / Responsive | The ESG mega-menu overflows the right edge of the viewport at **every** desktop width. Measured `getBoundingClientRect().right` vs `innerWidth`: 1024 → **+174px**, 1280 → **+203px**, 1440 → **+198px**, 1600 → **+117px**. Page `scrollWidth === clientWidth`, so there is no horizontal scroll to recover it. Visually confirmed at 1600×900: "ESG & CSR st…", "Climate risk &…", "Supplier & va… chain ESG" are cut through. | WCAG 1.4.10 Reflow; 2.4.11 Focus Not Obscured (AA); Nielsen #6 (Recognition over recall) | 3 ESG pages and (at 1024px) SBTi + Net Zero are unreachable by mouse for **100% of desktop users**. Keyboard users tab into content that is off-screen and cannot be scrolled to. | Root cause: `.mega { position:absolute; left:50%; translate:-50%; width:min(92vw,1040px) }` centres the panel on the *nav item*, not the viewport. Change to viewport-anchored: `position:fixed; left:50%; transform:translateX(-50%); width:min(94vw,1040px); max-height:calc(100vh - var(--nav-h) - 24px); overflow-y:auto;` — or anchor right: `left:auto; right:var(--gutter); translate:none`. |
| C3 | **Critical** | Mobile / Accessibility | With the mobile menu open, the close button is **invisible**. Its bars compute to `rgb(247,245,240)` on a menu background of `rgb(247,245,240)` — a measured contrast of **1.00:1**, at 55% opacity. The button is present and clickable at (311,28), 44×44, with a correct `aria-label="Close menu"`. It simply cannot be seen. There is no backdrop-click-to-close and no other close affordance. | WCAG 1.4.11 Non-text Contrast (requires 3:1); Nielsen #3 (User control and freedom) | On touch, the menu is a dead end — the only escape is tapping a nav link, i.e. an unintended navigation. Esc is unavailable. | In the `.is-menu-open` state force the dark token on the toggle: `.is-menu-open .nav__toggle{ color:var(--deep); border-color:rgb(10 61 68 / .35); opacity:1 }`, and swap the two bars to an X. Also add a click-outside/backdrop close handler for the mobile menu (currently only `a` clicks close it). |
| M1 | Major | Accessibility / Keyboard | The keyboard focus ring is `2px solid #c8a16a` (gold). Measured against the site's light surfaces: **2.20:1** on `--bone` `#f7f5f0`, **1.99:1** on `--bone-2`, **1.90:1** on `--bone-3`, **2.28:1** on the mega-menu panel. It passes only on dark ink (7.48:1). | WCAG 1.4.11 Non-text Contrast — focus indicators require 3:1 | Keyboard and low-vision users lose their position across **most of the site**, including the entire mega menu and the whole contact form. | Make the ring surface-aware. Add `--focus: var(--gold)` to the dark token block and `--focus: #6f5119` (≈7.0:1 on bone) to `:root`, then `:focus-visible{ outline:2px solid var(--focus) }`. Alternatively use a two-tone ring: `outline:2px solid var(--ink); box-shadow:0 0 0 4px var(--gold)`. |
| M2 | Major | Forms | All five text inputs and the select have a 1px border of `rgba(10,61,68,0.16)` on bone — measured **1.33:1**. | WCAG 1.4.11 (3:1 for control boundaries) | Field boundaries are near-invisible in bright light or on low-quality screens; users cannot tell where to tap. | Change the field border token to `rgb(10 61 68 / 0.42)` (≈3.1:1) and keep the 0.16 value for decorative rules only. |
| M3 | Major | Forms / Accessibility | Validation never sets `aria-invalid` (confirmed `null` after a failed submit), and the error `<span>` lives **inside** the wrapping `<label>`. The resulting accessible name was measured as **"Name *Please fill in this field."** — the error becomes part of the field's name rather than its description. | WCAG 3.3.1 Error Identification; 4.1.2 Name, Role, Value | Screen-reader users hear a mangled field name and get no programmatic invalid state. | In `showFieldError()`: `input.setAttribute('aria-invalid', String(!input.validity.valid))`. Give each `.field__err` an `id` and set `aria-describedby` on the input. Move the error span outside the `<label>` (or switch to `<label for>` + sibling error). |
| M4 | Major | CRO / Microcopy | Every CTA is the same generic "Contact us". On `carbon-supply.html`, **6 of 7** buttons read "Contact us" and point at the identical URL. No intent-matched paths exist anywhere on the site. | Nielsen #2 (Match between system and the real world); CRO — action specificity | A buyer ready for a quote, a buyer with a project to screen, and a buyer just browsing all get the same undifferentiated ask. Commitment cost is uniformly high; there is no low-friction entry point. | Differentiate by section intent and pre-fill the form's `topic`: "Get indicative pricing" → `contact.html?topic=Carbon%20supply`; "Send us a project to screen" → `?topic=Carbon%20projects`; "Request the project file" → `?topic=Project%20file`. Read the param in `initForm()` to preselect the select. |
| M5 | Major | Visual hierarchy / CRO | On `carbon-supply.html` the page close reads **"Tell us what you need."** and the footer immediately below reads **"Tell us what you need to stand behind."** — two near-identical CTA blocks stacked back-to-back, both with a gold "Contact us". | Nielsen #8 (Aesthetic and minimalist design) | Two competing closes dilute each other; the eye reads it as a rendering error. | Keep the page-level close. Change the footer "Start here" block to a different job — e.g. an email + direct-line block, or "Not ready to talk? See the sources behind every figure." |
| M6 | Major | Information architecture | **About is not in the primary navigation** — it exists only in the footer. And `sources.html`, the strongest credibility asset on the site ("every market figure with its named source and a link"), is buried inside the mega menu under a column headed "All of it". | Nielsen #6 (Recognition over recall), #7 (Flexibility and efficiency of use) | For an enterprise carbon buyer doing due diligence, "who are you" is a top-3 page. Burying it and the sources page hides exactly the evidence that closes a deal. | Add "About" to the primary nav (4 links still fits: currently only 3 + CTA). Promote "Sources & data" to a first-class footer column head and link it from the proof band on the homepage. |
| M7 | Major | Consistency | "ESG & sustainability" has a disclosure chevron revealing 19 sub-pages. "Carbon supply" — which now contains Carbon projects at `#pipeline` — has **no** disclosure at all, so nothing in the nav reveals that carbon project development exists. | Nielsen #4 (Consistency and standards) | The service you most want to sell is invisible from the nav. Inconsistent affordances teach users the chevron is arbitrary. | Add a matching `data-mega-wrap` disclosure to "Carbon supply" containing: Spot / Portfolio / Offtake, Carbon project development, The Five Checks. |
| M8 | Major | Perceived performance | The `h1` and 32 of 34 `.reveal` elements start at `opacity < 0.1` and animate in. The homepage captured mid-load on both desktop and mobile showed the headline **entirely absent** from the first paint while the photo was fully rendered. | WCAG 2.2.2 (adjacent); Core Web Vitals — LCP | The LCP text candidate is deliberately deferred. On a slow connection the user sees a full-screen photo with no words. Browser find-in-page also cannot reveal off-screen `.reveal` content. | Exempt above-the-fold content from the reveal: do not apply `.reveal` / `.kinetic` opacity-0 to `.hero h1`, `.hero__b`, or `.hero .btns`. Animate transform only, or start them at `opacity:1`. |
| M9 | Major | Typography | Every form label is 11px, `text-transform:uppercase`, IBM Plex Mono, at `rgba(6,40,46,0.66)`. Contrast passes (≈5.3:1) but 11px all-caps mono with letter-spacing is the least legible configuration available. | WCAG 1.4.4 (adjacent); legibility research on all-caps text | Slows form completion and raises error rates for the exact audience (senior buyers, often 45+) being targeted. | Set form labels to 14px, sentence case, `--sans`, weight 500, `rgb(6 40 46 / 0.9)`. Keep the mono/caps treatment for decorative eyebrows only. |
| M10 | Major | Mobile UX | With the full-screen fixed menu open (`position:fixed`, z-index 190), `document.body` computed `overflow: visible` — background scroll is not locked. The menu itself overflows (`scrollHeight` 881 vs `clientHeight` 812), so **"Contact us" inside the menu sits below the fold and is clipped**. | Nielsen #1, #3 | Scroll-chaining on iOS; the menu's own primary CTA is cut off on a 375×812 phone. | Add `.is-menu-open body{ overflow:hidden }` (or `overscroll-behavior:contain` on the menu). Reduce the menu's vertical rhythm so the CTA fits, or pin the CTA to the menu's bottom edge. |
| M11 | Major *(needs per-glyph verification)* | Contrast over imagery | The real hero AVIF pixels were composited with the actual scrim gradient alpha. Against the **brightest** pixels behind the text: hero eyebrow **2.65:1** (requires 4.5), `h1` **2.73:1** (requires 3.0). Against the average background both pass comfortably (6.6:1 and 14.1:1). | WCAG 1.4.3 Contrast (Minimum) | The earth-at-night photo has city lights directly under the text. Where a glyph lands on one, it drops below threshold. Real but localised. | Raise `.scrim--hero`'s first stop from `0.82` to `0.90` and push the 0.62 stop out to 48%, or add `text-shadow:0 1px 18px rgb(4 26 30 / .8)` to `.hero .label` and `.hero h1`. **Verify with a per-pixel contrast tool** (e.g. axe DevTools' image-text check) before signing off. |
| M12 | Major | Contrast | The "privacy policy" link inside the consent checkbox label measures **4.39:1** at 15px. | WCAG 1.4.3 (requires 4.5:1) | Marginal fail on the one link standing between a user and a legal consent action. | Darken the inline link colour to `#6f5119` (the existing `--accent-text` token), giving ≈7.0:1. |
| M13 | Major | Trust / Credibility | The footer offers an email, a phone number, a LinkedIn link and "Based in India". There is **no registered entity name, no address, no named team, no client logos, no registry/standard affiliations (Verra, Gold Standard, I-REC), and no verifier named** for the flagship Gujarat/Rajasthan project — the project is described as "third-party verified" without saying by whom or under which methodology. | Nielsen #10 (Help and documentation); B2B trust heuristics | An enterprise buyer committing to a carbon position they will have to defend to auditors cannot verify who they would be contracting with. This is the largest non-technical conversion drag on the site. | Add to the footer: registered company name, CIN/registration number, and registered address. Add a "The team" block to `about.html` with real names and credentials. On the impact section, name the standard, methodology ID, verifier (VVB) and registry record, and link to the public registry listing. **These facts must be supplied — none should be invented.** |
| m1 | Minor | Touch targets | The consent checkbox renders **22×22 px**. | WCAG 2.5.8 Target Size (Minimum), 24×24 | Likely passes via the spacing exception (nothing else within 24px), but needlessly small on touch. | `input[type=checkbox]{ width:24px; height:24px }`. |
| m2 | Minor | Mobile UX | The sticky CTA bar (`position:fixed`, z-index 180, "Contact us · or email") has no `aria-label`, no `role`, and no dismiss control. | Nielsen #3 (User control and freedom) | Persistent chrome the user cannot turn off; unlabelled landmark-adjacent region. | Wrap in `<aside aria-label="Quick contact">` and add a dismiss button that sets a `sessionStorage` flag. |
| m3 | Minor | Navigation | The mega menu opens on `pointerenter` with **0ms** hover-intent delay and closes instantly on `pointerleave`. | Nielsen #3 | A pointer crossing the nav en route elsewhere triggers a full-width panel; a diagonal move toward the panel can close it. | Add a ≈120ms open delay and a ≈250ms close delay (the existing `closeTimer` can be reused for the open path). |
| m4 | Minor | Semantics / SEO | Breadcrumbs render as a bare `<ol class="crumb">` with no `<nav aria-label="Breadcrumb">` wrapper. `BreadcrumbList` JSON-LD is present on all 19 ESG sub-pages but **absent** on `carbon-supply.html`, `esg-sustainability.html`, `energy-attribute-certificates.html` and `about.html`. Those same 4 pages also lack the `FAQPage` schema every sub-page has. | WCAG 1.3.1 (adjacent); ARIA APG; schema.org | Screen-reader users get an unlabelled list; the 4 highest-value commercial pages forfeit rich results. | Wrap the `<ol>` in `<nav aria-label="Breadcrumb">` in `render.mjs`. Emit `BreadcrumbList` + `FAQPage` for the four top-level pages too. |
| m5 | Minor | Motion | The homepage story is a 200vh scroll-pinned section delivering 3 short scenes, with an "01 / 03" counter and no skip control. (Correctly disabled under reduced-motion and below 940px.) | Nielsen #3 | Two full viewports of scroll to read ≈75 words, with no way past. | Add a "Skip the story" link, or let the six rail dots (already keyboard-accessible) jump scenes directly. |
| m6 | Minor *(latent)* | Forms | In the success path, `submit.textContent = 'Sending…'` destroys the button's arrow `<svg>`, and restoring `original` (a text string) restores only the text. The arrow never returns. | — | Currently unreachable because C1 short-circuits before this line. **It will surface the moment the access key is set.** | Target a `<span class="btn__label">` instead of the button's own `textContent`, or save and restore `innerHTML`. |
| m7 | Minor *(intentional)* | Launch readiness | All 28 pages carry `<meta name="robots" content="noindex, nofollow">`, `robots.txt` is `Disallow: /`, and `sitemap.xml` is an empty `<urlset>`. Canonicals point at the `kishan0088.github.io/Offsetease_V4.4/` preview host. | — | Correct for a preview. Becomes a total-blackout SEO failure if shipped as-is. | Pre-launch checklist: strip the `noindex`, open `robots.txt`, populate the sitemap, repoint canonicals to the production domain. |

## Legend

- **Critical** — breaks a primary user path or conversion mechanism outright.
- **Major** — fails a WCAG 2.2 AA success criterion, or measurably suppresses conversion / comprehension.
- **Minor** — quality, consistency or polish; no path is broken.
- *(needs per-glyph verification)* / *(latent)* / *(intentional)* — flagged where a finding requires further technical testing, is not yet reachable in the current build, or is a deliberate pre-launch state.

*No issue in this document is inferred. Each was observed on the live site or measured directly from the deployed source.*
